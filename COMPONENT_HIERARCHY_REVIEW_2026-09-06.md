# Component Hierarchy Review — 2026-09-06

## Core rule
The site now follows one hierarchy principle: **identity → value → proof → detail → next action**.
Images support identity and proof; they do not precede the message.

## Home
Old order:
role/headline + photo → metrics → mandate → systems canvas → flagship proof → portfolio CTA

New order:
**Mahmoud Salama → role → positioning headline → proof line → CTAs → photo → metrics → current mandate → flagship proof → systems canvas → contact CTA**

Why:
- Name must be identified before the visitor interprets the portrait.
- The portrait is supporting evidence of identity, not the primary message.
- Concrete proof should come before the abstract systems canvas.
- The final action should be Contact, because Portfolio and Projects have already been offered earlier.

Desktop:
- Text and image remain side-by-side.
Mobile:
- Name/text/CTA appear before the portrait.

## Portfolio
Order remains:
hero → executive snapshot → executive map → MedIQ → SAP → career arc → governance/recognition → CTA.
Added contextual links only after complete sections.
Why:
- Executive map explains the operating model before deep case studies.
- Links at section endings do not interrupt reading.

## Projects
Desktop:
image left → title/content right.
Mobile:
**title/role/description/action first → image second.**
Project links remain at the bottom of the card.
Why:
- On small screens the user should know what project they are looking at before spending vertical space on an image.
- A project reference is a secondary action, so it belongs after the description.

## Technologies
New order inside hero:
headline → **ARCHITECT / LEAD / DELIVER / OPERATE rail** → detailed four strategy cards → technology directory.
Why:
- The executive interpretation must come before the 161-item technical evidence.

## Architecture
Order:
hero → architecture method → principles → flagship SAP case → contextual project link.
Why:
- First explain how Mahmoud thinks, then the principles, then prove it with a real case.

## Experience
Order:
hero → career progression ribbon → detailed timeline → Leadership link.
Why:
- The reader gets the career thesis in seconds, then the chronology.

## Leadership
Old:
current evidence → career progression → current operating model → playbook.
New:
**current evidence → current operating model → career progression → transformation playbook.**
Why:
- For an executive profile, present-day scope should precede history.

## Governance
Order:
governance thesis → national roles → common thread → Recognition link.
Why:
- Recognition follows institutional responsibility naturally.

## Recognition
Order:
recognition thesis → recognition cards → Projects link.
Why:
- After recognition, the logical next question is “show me the underlying work.”

## About
New order:
**Mahmoud Salama → professional identity → current role → geography → education → Experience / Leadership links.**
Why:
- Identity and present responsibility matter more than biography or education at this career level.

## Contact
New order:
**Mahmoud Salama → opportunity statement → Email → LinkedIn → Location.**
Why:
- Contact pages should optimize for conversion. Email is the primary action; LinkedIn validates identity; location is supporting context.

## Global link placement
- Hero: only the two highest-value navigation actions.
- Section body: no inline link clutter.
- End of section: one contextual “next logical step.”
- Final page CTA: conversion / Contact where appropriate.
