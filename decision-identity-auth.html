PUBLIC DECISION NOTE

Identity & Authentication: Centralize Trust, Keep Authorization Contextual

A public architecture note on OAuth 2.0/OIDC identity boundaries and application authorization.

Context

Multiple applications need consistent identity while retaining domain-specific permissions.

Decision

Use standards-based centralized authentication where appropriate, while keeping fine-grained authorization tied to application and business context.

Why

Authentication and authorization solve different problems. Conflating them makes permissions harder to reason about and change.

Trade-offs

Central identity increases dependency on a shared service and requires careful availability, lifecycle and integration design.

Boundary

This note intentionally does not publish provider configuration, token settings, endpoints, role mappings or security controls.

Public boundary

This note explains a reusable decision pattern. It intentionally excludes confidential topology, credentials, security configuration, internal endpoints and other operationally sensitive details.
